# Олимпийский исследовательский портал

Статический русскоязычный каталог научных публикаций об олимпизме,
Олимпийском движении и олимпийском спорте.

Главный принцип: **достоверность важнее количества**. В публичный каталог
попадают только записи с подтверждённой тематической связью.

## Что изменилось по сравнению с ранней версией

- Публичная выдача содержит только подтверждённые записи (`rejected`,
  `review` и `subject_olympiad` в неё не попадают).
- Тематический фильтр переработан после независимого аудита: он больше не
  принимает случайные совпадения (имена авторов, «движение» без олимпийского
  контекста, школьные олимпиады, одиночную подстроку «олимп»).
- Каждая принятая запись объясняет включение: `relevance_reason` +
  `relevance_evidence` (видно в карточке и в подробном просмотре).
- Удалены сгенерированные «аннотации» вида «Научное исследование по теме…».
  Фильтр релевантности больше не читает такие тексты как доказательство.
- Аннотации очищаются от HTML-сущностей, `&s;s`, `&#x0D;`, УДК/ББК,
  издательских сведений и дублирующихся фрагментов.
- Библиографическая ссылка формируется из реальных данных, без фиктивного
  «Автор не указан»; добавлены поля `doi`, `container` и `isbn`.
- Год публикации подтверждается полем или DOI/URL. Записи без подтверждённого
  года не публикуются.
- Данные имеют единый контракт `{ "metadata": {...}, "data": [...] }`.
- Избранное сохраняется между перезагрузками страницы.
- Токены не хранятся в коде.

## Источник данных

Актуальный источник — `generated/master_dataset.csv` (выгрузка Google Sheets,
1639 записей, ID вида `OLY-0005`). Он формируется скриптом
`scripts/build_master_dataset.py`.

Старый корневой `web_data.json` и `generated/web_data.json` — **устаревшие
легаси-массивы** (`rec-00001…`, 1556 записей) без тематической проверки.
Они сохранены как история, но сборка и интерфейс их не используют:
`build_dataset.py` предупреждает об этом, а `app.js` читает только
`public/web_data.json`.


## Категории

1. Олимпийское образование и просвещение
2. Пропаганда, философия и культурология
3. История и наследие олимпизма
4. Этика, честная игра и антидопинг
5. Политика, геополитика и глобальные вызовы
6. Психология олимпийского спорта
7. Менеджмент, маркетинг и экономика Игр
8. Спортивная медицина, физиология и биомеханика
9. Подготовка олимпийского резерва и тренировка
10. Теория и методология олимпийского движения
11. Без категории

Категория присваивается только при совпадении ключевых слов. Если оснований
нет, ставится «Без категории» — запись не приписывается к направлению наугад.

## Как определяется релевантность

Запись получает один из четырёх статусов:

- `accepted` — связь с олимпизмом подтверждена **содержательными**
  признаками в названии, аннотации или ключевых словах;
- `review` — данных недостаточно, год не подтверждён или признаки спорны;
- `rejected` — тематика не относится к каталогу;
- `subject_olympiad` — школьная или предметная олимпиада (не Олимпийские
  игры). Такие записи не попадают в публичный каталог.

Решение всегда сопровождается объяснением (`relevance_reason`) и списком
конкретных подтверждений (`relevance_evidence`). **Запись без
`relevance_evidence` не публикуется** — это проверяется автоматически.

### Что считается доказательством, а что нет

Принимаются только содержательные маркеры, разделённые по направлениям:

1. олимпизм и олимпийские ценности;
2. Олимпийские игры;
3. Олимпийское движение и МОК;
4. олимпийское образование;
5. олимпийская философия и история;
6. олимпийское наследие;
7. паралимпийское движение;
8. антидопинговая политика и WADA;
9. спортивная наука — только при явной олимпийской квалификации спортсменов
   («элитные», сборная, олимпийский отбор).

**Не считаются доказательством:**

- имена авторов (например, «Олимпиада Иванова»);
- слово «движение» без олимпийского контекста
  («революционное движение», «христианское студенческое движение»);
- школьные и предметные олимпиады («Олимпиада по физике», «Physics Olympics»);
- одиночное совпадение подстроки «олимп»;
- упоминание Олимпийских игр как внешнего контекста (геохимия вблизи
  олимпийских объектов, охрана труда, инфраструктура, управление отходами);
- неолимпийские употребления слова («Olympic Dances», отель, авиалинии).

Если название принадлежит другой научной дисциплине, а олимпийские термины
найдены только в аннотации, запись уходит в `review`: вероятна склейка
разных источников.

### Структурная фильтрация

Из публичного каталога исключаются служебные разделы книг: Frontmatter,
Contents, Index, Illustrations, Bibliography, Acknowledgements, List of
Abbreviations и одиночные структурные слова. Полноценная статья при этом
не отбрасывается только из-за номера главы в названии: заголовок главы
с содержательным названием и аннотацией проходит дальше.

### Ограничения автоматической проверки

Алгоритм основан на правилах и ключевых словах, а не на смысловом понимании
текста. Он:

- надёжно отбрасывает явно посторонние темы и находит прямые олимпийские
  маркеры;
- может ошибочно отнести к `review` публикацию, где связь выражена
  иносказательно или только в полном тексте;
- не умеет читать платные публикации без аннотации.

Поэтому записи со статусом `review` требуют участия человека.

### Как проверять спорные записи

1. Откройте `public/review.json` и просмотрите `relevance_reason`.
2. Проверьте публикацию по DOI или ссылке на источник.
3. Если тематика подтверждается — добавьте подтверждающие данные в исходный
   файл и пересоберите каталог.
4. Если не подтверждается — запись остаётся в `rejected.json` с причиной.

Записи не удаляются: они сохраняются с причиной решения.

## Запуск локально

```bash
python -m http.server 8000
```

Откройте `http://localhost:8000`. Открывать `index.html` напрямую из файловой
системы не рекомендуется: браузер заблокирует загрузку данных.

## Сборка датасета

```bash
python build_dataset.py                 # из generated/master_dataset.csv
python build_dataset.py --input путь.csv --out public
python verify_dataset.py                # проверка перед публикацией
```

Сборка атомарна: при сбое рабочие файлы не перезаписываются пустыми.

Порядок прохода в `build_dataset.py`:

1. нормализация (DOI/ISBN, год, **очистка аннотаций до классификации**);
2. структурная проверка — служебные разделы отсекаются;
3. дедупликация (DOI, ISBN, название + автор + год, гомоглифы);
4. тематическая проверка (`accepted` / `review` / `rejected` / `subject_olympiad`);
5. записи без подтверждённого года или без `relevance_evidence` → `review`.

## GitHub Actions

Workflow `.github/workflows/auto_collect.yml`:

1. устанавливает зависимости;
2. запускает тесты;
3. собирает каталог;
4. проверяет целостность (`verify_dataset.py`).

Права токена ограничены чтением репозитория. Автоматический `git push` и
публикация не выполняются: результат проверяется вручную.

## Библиографические ссылки

Формат, принятый в проекте:

```
Gogovor A. Contemporary Disease Management in Quebec / A. Gogovor,
M. Savoie, Y. Moride, M. Krelenbaum, T. Montague //
Healthcare Quarterly. – 2008. – URL: https://example.org/article
(дата обращения: 10.11.2026).
```

Это **принятый в проекте формат**, а не подтверждённое соответствие
конкретному ГОСТ. Дата обращения вычисляется при генерации ссылки.

## Известные ограничения

- Часть записей имеет повреждённые годы публикации в источнике. Они переведены
  в `review` и требуют проверки по первоисточнику.
- Тексты аннотаций на русском появляются только после реального перевода;
  при отсутствии перевода показывается оригинал или честное сообщение.
- Запись с неполными метаданными может получить неполную ссылку — это
  осознанное решение вместо выдумывания данных.
- AI-классификация не принимает решение о научной релевантности: только
  уточняет направление уже принятых записей.
