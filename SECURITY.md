# Политика безопасности

## Хранение секретов

Секреты **никогда** не хранятся в репозитории. Они передаются только через
переменные окружения или секреты GitHub Actions.

| Секрет | Где задаётся | Назначение |
|---|---|---|
| `VK_GROUP_TOKEN` | GitHub Secrets / локальное окружение | Токен бота сообщества ВКонтакте |
| `VK_GROUP_ID` | GitHub Secrets / локальное окружение | Числовой ID сообщества для Long Poll |
| `GEMINI_API_KEY` | GitHub Secrets / локальное окружение | Необязательная AI-классификация |
| `GOOGLE_SHEETS_CSV_URL` | Переменная Actions | Источник данных |

Правила:

1. В коде нет значений по умолчанию, похожих на действующие учётные данные.
2. При отсутствии обязательного секрета скрипт завершается с понятным
   сообщением и **не пытается** авторизоваться.
3. Значения секретов не пишутся в логи, JSON, CSV, HTML и JavaScript.
4. Файлы `.env` и локальные конфиги исключены через `.gitignore`.

## Настройка секретов GitHub Actions

1. Откройте репозиторий → **Settings** → **Secrets and variables** → **Actions**.
2. Нажмите **New repository secret**.
3. Добавьте:
   - `VK_GROUP_TOKEN` — токен сообщества (получается в управлении сообществом:
     «Работа с API» → «Создать ключ»);
   - `VK_GROUP_ID` — числовой ID сообщества;
   - `GEMINI_API_KEY` — только если нужна AI-классификация.
4. В workflow используются `secrets.VK_GROUP_TOKEN` и `secrets.VK_GROUP_ID`.

## Что важно знать о ранее опубликованном токене

Ранее токен сообщества был записан прямо в исходном коде и попал в историю Git.
**Удаление из текущего файла не отменяет его действия.** Токен следует считать
скомпрометированным.

Обязательные действия владельца проекта:

1. Отозвать старый токен в настройках сообщества ВКонтакте.
2. Выпустить новый токен.
3. Добавить его как секрет `VK_GROUP_TOKEN` в GitHub Actions.
4. Не возвращать токен в код ни в каком виде.

Переписывание истории Git (`filter-repo`, `filter-branch`) автоматически не
выполнялось: это необратимая операция, требующая отдельного решения владельца.

## Бот ВКонтакте и CI

Бот использует `VkBotLongPoll` — постоянный процесс, ожидающий события.
Он **не запускается** в еженедельном workflow: для Long Poll нужен постоянно
работающий хостинг (VPS, PaaS, отдельный сервис). CI занимается только сборкой
и проверкой данных.

## Обработка внешних данных

- Сетевые запросы имеют таймауты и ограниченное число повторов.
- При ошибке внешнего сервиса не создаётся вымышленный текст: запись остаётся
  с честным статусом аннотации.
- Автоматическая публикация изменений отключена: результат проверяется вручную.

## Сообщение об уязвимости

Если вы обнаружили проблему безопасности, не создавайте публичный issue с
деталями эксплуатации. Сообщите владельцу репозитория напрямую.
